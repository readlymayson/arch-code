# Выбор AI-агентного фреймворка: CrewAI vs LangGraph vs AutoGen

## Зачем

При построении multi-agent системы генерации кода (или любого другого агентного пайплайна) встаёт вопрос: какой фреймворк выбрать? Каждый из CrewAI, LangGraph и AutoGen решает схожую задачу, но с разными компромиссами. Ошибочный выбор приводит к избыточному расходу токенов, потере контроля, или долгому циклу разработки.

## Процесс выбора

### Шаг 1: Определить тип требуемого пайплайна

Задайте себе эти вопросы:

| Вопрос | Если да → склоняйтесь к | Если нет → склоняйтесь к |
|---|---|---|
| Задача естественно разбивается на **роли** (исследователь, писатель, редактор)? | CrewAI | LangGraph |
| Нужен **тонкий контроль** над потоком (циклы, ветвления, условные переходы)? | LangGraph | CrewAI |
| Агентам нужно **писать и выполнять код** (собственная песочница)? | AutoGen | CrewAI или LangGraph |
| Нужна **production-ready** функциональность (checkpointing, streaming, HITL)? | LangGraph | CrewAI (ограничено) |
| Важна **быстрота прототипирования** (первые 30 минут)? | CrewAI | LangGraph (больше бойлерплейта) |
| Бюджет токенов **ограничен**, нужна эффективность? | LangGraph (контролируемый расход) | CrewAI (3-5x больше) |

### Шаг 2: Сопоставить с характеристиками фреймворков

| Критерий | LangGraph | CrewAI | AutoGen |
|---|---|---|---|
| **Модель** | Граф состояний (state machine) | Ролевые агенты + задачи | Групповой чат агентов |
| **Контроль** | Максимальный (явные узлы, рёбра, состояние) | Средний (много "магии") | Средний (беседа) |
| **Циклы/ветвления** | Нативный граф — легко | Сложно, нужны обходные пути | Возможно через групповой чат |
| **Расход токенов** | Контролируемый | 3-5x выше (ролевая обёртка) | Высокий ("светская беседа") |
| **Code execution** | Нужно реализовывать | Нужно реализовывать | **Встроенная Docker-песочница** |
| **Production-ready** | Да (checkpointing, streaming, HITL) | Ограничено | Меньше интеграций |
| **Кривая обучения** | Крутая | Пологая | Средняя |
| **Лучше всего для** | Сложные пайплайны с циклами | Content creation, быстрые MVP | Code generation, multi-agent дискуссии |

### Шаг 3: Выбрать стратегию совмещения (если нужно)

Фреймворки можно комбинировать, но с осторожностью:

| Комбинация | Смысл | Когда оправдана |
|---|---|---|
| **CrewAI → LangGraph (инструмент)** | CrewAI управляет ролями, LangGraph — инструмент для циклического подпроцесса | Есть Architect + сложный цикл generate→test→fix (текущий проект) |
| **Только LangGraph** | Всё — граф состояний, каждая роль — узел графа | Нужен контроль, проект стабилен, ролей ~3 |
| **Только CrewAI** | Все роли — CrewAI-агенты с sequential/hierarchical process | Быстрое прототипирование, чёткие роли, цикл реализуется через hierarchical |
| **Только AutoGen** | Агенты общаются в групповом чате | Акцент на code execution, human-in-the-loop |

**Правило:** Не комбинируйте "просто потому что можно". Каждый фреймворк — это оверхед (токены, задержка, сложность). Если одна задача укладывается в один фреймворк — используйте один.

### Шаг 4: Проверить совместимость версий

**Важно:** CrewAI требует Python < 3.14 (на 2026 год). При Python 3.14+ сначала проверьте `pip install crewai==<last-version>`. Если не ставится — создавайте venv с Python 3.13.

```bash
# Проверить доступные версии Python
py --list

# Создать venv с Python 3.13
py -3.13 -m venv .venv

# Установить
.venv\Scripts\pip install -r requirements.txt
```

## Пример: решение для генерации кода

Ситуация: нужно генерировать Node.js код по style-guide и API-контрактам, тестировать в Docker, исправлять ошибки.

### Решение: CrewAI + LangGraph (гибрид)

```
CrewAI:
  └─ Architect (V4-Pro, инструменты: ReadKnowledgeTool + LangGraphCodingTool)
       └─ LangGraphCodingTool:
            └─ generate → test → (max 3) → END  (V4-Flash + Docker)
```

**Почему:**
- Architect как роль нужен для чтения документации — это естественно для CrewAI
- Цикл generate→test→fix — граф состояний, это естественно для LangGraph
- Docker — отдельный слой, не зависит от фреймворка

### Альтернатива: только CrewAI (multi-agent)

Если ролей станет больше (Coder, Tester, Reviewer):

```
CrewAI (Process.hierarchical):
  └─ Architect → Coder → Tester → (Manager решает: retry или END)
```

**Почему:** упрощение — один фреймворк вместо двух. Минус — retry-цикл через hierarchical process, меньше контроля.
